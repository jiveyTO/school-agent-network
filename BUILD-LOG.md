## Day 1 — Monday, October 26, 2026

- **Concept finalized: School Agent Network.** Three cooperating agents on one shared fact layer:
  - *School Agent* — the source of truth; turns school newsletters and notices into structured facts with provenance.
  - *Parent Agent* — a personal secretary for one family, tuned to their child: filters school facts to that family and acts on deadlines.
  - *Group Agent* — lives in the parent group chat; answers repeated questions from school-verified facts and shares privacy-safe aggregate counts only, never individual family information.
  - Each agent works on its own; together they are better. Authority order: official school > parent-seeded "shell" school agent > group > a parent's own sources.
- **Design docs written** (`docs/`): the shared fact schema (16 fields, source quote required on every fact), Parent Agent architecture (a family profile + a prompt, run event-driven from one shared backend), the three-layer onboarding design, and the Parent Agent soul & safeguards spec (private-by-default data tiers, an outbound privacy self-check on everything the agent sends, aggregates with a minimum cohort, audit log).
- **Bootstrapping design:** if the school doesn't participate, parents connect sources themselves, a parent-seeded "shell" School Agent is created for the school, and the school can later claim it and inherit its history.
- **Demo privacy rule set:** all demos use fictional Maple Grove Elementary data only. Real school material is a private local test input — it is gitignored, never committed, and never shown on screen.
- **Mock newsletter written** (`data/mock-newsletter.txt`): a fictional Maple Grove Elementary week (Nov 2–6) used as the demo input.
- **Phase 1 built** (with Muse Code): the School Agent — a small Node server (standard library only, no build step) that calls the Meta Model API from the server side and extracts the newsletter into `data/facts.json` exactly per the fact schema, plus a phone-width demo page with the newsletter, a Run button, the facts list, and an event log.
- **Phase 1 verified live:** a real API run extracted 22 facts; every fact's source quote checked verbatim against the newsletter; a re-run produced 23 (one announcement split in two) — extraction is non-deterministic, so a known-good `facts.json` will be frozen before the demo video is recorded.
- **Docker:** the run moved into `docker compose` (node:20-alpine, project mounted) so the server keeps running independent of any terminal session.

## Day 3 — Wednesday, October 28, 2026

- **The pivot — School Agent Network becomes ParentLoop.** Morning testing exposed the original model's weakness: every useful source sits behind a login, and asking parents to hand over credentials (or wait for a school to sign up) kills adoption. Jason reframed the product: *a shared repository of context that parents maintain together, organized by hub* — "GitHub for parent context." One parent founds a hub for a context (a school, a class, a team), invites other parents through channels that already carry trust (a link in the existing WhatsApp group / email), and members add the material — newsletters, notices — that the extraction pipeline turns into verified facts stored per hub. Each family's private Parent Agent then reads across all of that family's hubs. Positioning locked: **hubs hold shared context only — a family's private details never enter a hub.**
- **ParentLoop migration built and verified** (Muse): new tables (hubs, hub_members, invites, join_requests, materials, children) with facts moved into the database carrying hub + material ids; in-place migration preserved both existing profiles (demo + owner test profile; pre-migration backup kept); sources rebuilt **credential-free** (username/secret columns deleted — no logins, no scraping, per the Oct 27 decision); Gmail kept as an optional intake that files an email into a chosen hub. Demo seeds: Hub A "Grade 3 — Maple Grove Elementary" (24 facts, Rivera family as founder/admin), Hub B "U9 Hockey — Maple Grove" (5 facts) with a **Friday Nov 6, 6:30 PM game colliding with Hub A's Fall Festival**; one pending join request (fictional Sam Chen) seeds the approve/decline demo.
- **Parent Agent v2:** reads database facts across all of the family's hubs, groups its output by hub, and adds deterministic **cross-hub conflict detection**. Verified live: it flagged "Fall Festival Dance (Grade 3 — Maple Grove Elementary) overlaps U9 Hockey game (U9 Hockey — Maple Grove) on Friday, Nov 6" under CONFLICTS and closed with the exact PRIVACY CHECK line.
- **Join/invite surface:** `/join/<token>` landing shows only the hub name, the inviter's first name, and the member count (contract-tested non-leakage); accepting runs onboarding first when the visitor has no profile. Anyone can request to join; a hub admin approves (WhatsApp-group model).
- **Google Classroom probe — verdict: blocked by design.** A read-only OAuth probe against a student account returned `access_not_configured`: district-managed student accounts cannot authorize third-party apps until the district admin marks the app trusted. Conclusion recorded honestly in the design docs: the school-signs-up / community-upload model is the one that respects district permission gates; student-account integrations are an institutional decision, not a technical one.
- **Product-name collisions checked:** "Parent Hub" collides with a UK edtech company of the same name; "ParentLoop" is used by an existing school-communication app. ParentLoop stays as the working title for the hackathon; a rename is a find-and-replace, deliberately not a build-week blocker.
- **Founder click-through round 1 (Jason, evening):** removed the onboarding portal-sources section (bookmarks belong to the old model), removed the standalone paste-a-newsletter section (material now enters through hubs), and **removed Gmail from the page entirely** — the endpoints and token store stay in code, dormant: an unknown product must earn email access with trust before asking for it, and the demo should not dead-end judges at an OAuth wall. Onboarding is now one short form → My hubs.

## Day 4 — Thursday, October 29, 2026

- **Audience scopes shipped (Parent Agent v3).** Every fact and material now carries a scope — school / grade / class — stamped by extraction in the same single model call (labels are free; filtering is plain code). Enforcement is server-side: a profile outside a fact's scope never receives it from any endpoint. Design case from the owner's real school: three Grade 2 classes (straight Grade 2, a 1/2 split, a 2/3 split) — grade scope spans all three, class scope keys on the teacher/classroom, so split classes work by enrollment, not grade arithmetic. Demo re-stamp: 22 school / 1 grade / 1 class in Hub A; an out-of-scope test profile (Grade 9) receives school-scoped facts only. "Who is this for?" selector on uploads defaults to *Let ParentLoop decide*; uncertain extractions choose the narrower scope.
- **Hub model locked:** hubs stay flat (no sub-hubs); one hub per school is the default shape; a hub of one is the solo mode — the founder's on-ramp; invites are an upgrade, not a requirement.
- **School-hub identity:** structured creation (School name + City, later + Province/State + Country) with the display name composed by the app ("<School> — <City>"). Normalized identity keys (case/punctuation collapsing, St→Saint, CES/CSS expansions, nickname map Joe→Joseph, province/country alias maps) power a **one-hub-per-school guard**: an exact match returns 409 with a Request-to-join card (no fork, no override); a near match returns a "looks like" card where the founder may still create a genuinely different school. Legacy hubs match on equal-or-empty parts.
- **Navigation restructure:** three tabbed views (My hubs / Evening check / My family) with top-of-page landings (fixed a save-then-scroll-to-bottom bug); responsive single column at phone width, 960px two-column hub detail on desktop; the always-open create form retired behind a "+ Start a hub" toggle; hub cards replaced the hub dropdown as the picker; **zero-hub welcome state** — a parent with no hubs sees only "Start your first hub," no empty member furniture.
- **Reading experience:** extraction emits a `group_label` per fact (the newsletter's own section heading); hub detail renders **one card per source material** with collapsible section groups inside; a deterministic "For your family" strip pins deadline/action facts matching the viewer's children (honest reason chips — guidance items never qualify); repeated "From the newsletter" quotes consolidated under one shared header. Progress bars with staged status text on the model waits (add material, evening check). Facts stay atomic in the store — grouping is presentation only, so the agent's citations and conflict logic are untouched.
- **Founder conveniences:** create form remembers city/province/country; kind question moved to the top (it drives the fields below); **website-link autofill** — paste a school or team/league website and one model call fills the identity fields for confirmation (parsed school names feed the same uniqueness guard); **structured team hubs** (Sport + Level/League — House League / Select / Rep / A / AA / AAA); **invite share buttons** — Email (mailto), WhatsApp (wa.me), Copy link, all on one token, no server-side sending.
- **Privacy scrub:** before anything public, all real names came out of the repo and the hosted copy — the real school/city became fictional fixtures (St. Nicholas, Willow Creek). Verified live: the public page contains no real school or town names.
- **Cloud Run deploy — ParentLoop is live:** https://parentloop-964717527488.northamerica-northeast2.run.app (project `school-agent-network`, region northamerica-northeast2, public, max instances 1). Verified end to end: homepage, onboarding state, demo activation, and an evening check returning nudges and conflicts. Deploy surfaced the build's main structural gap, now on record: **the app holds one global active family — there are no accounts yet**, so every visitor to the public link shares one state.
